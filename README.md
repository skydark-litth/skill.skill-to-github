# skill-to-github

把一个 **WorkBuddy 用户级 skill 目录**同步（发布 / 更新 / 备份）到 **GitHub 仓库**的技能。使用 git over SSH，二进制安全、支持任意文件大小、可一次提交多个文件。

## 适用场景

当你想把本地某个 skill（通常在 `C:\Users\USER\.workbuddy\skills\<skill-name>\`）：

- 发布 / 上传到 GitHub；
- 更新已同步的仓库（本地改动后对齐远程）；
- 做版本控制或云端备份。

也适用于**任意本地项目目录**（非技能文件夹）：此时 Step 2 的 README 内容比对按实际项目判断（项目 README 通常不写 `version:`，一律以内容是否匹配为准），且当目标为**公开仓库**、项目又是**无许可证上游代码的衍生作品**时，会先提示版权 / 再分发风险。

## 核心特性

- **双目标显式确认**：必须由用户明确指定「本地 skill 完整路径」与「`owner/repo`」，并先核验本地 `SKILL.md` 名称，避免读错技能或覆盖错误项目。
- **仓库缺失时引导网页创建**：探测到目标仓库不存在，会给出 https://github.com/new 与精确的名称 / owner / 可见性，用户在网页创建后再继续（SSH 密钥本身不能创建远程仓库，此方式无需额外 token）。
- **上传前泄密 / 隐私检查**：每次上传 / 更新前对技能做文件清单、密钥模式、绝对个人路径、嵌套 `.git`、**本地特定标识（脱敏）**五项检查；发现任何可疑即停止并汇报，由你决定后再继续。
- **README 保持最新**：缺失时经你同意由大模型自动生成；若远程 README 与当前技能内容不一致，经你同意由大模型按「旧 README + 新技能的变化」更新——保留旧结构语气、刷新特性 / 工作流 / 脚本清单（版本号以内容为准，不强制维护）。
- **git 内置验证**：用 `git status` / `git diff` + `git fsck --full` 校验变更与对象完整性，以推送结果（ref 前进、exit 0）确认，无需再把文件下载回本地比对。
- **自我更新**：遇到技能尚未覆盖的问题，先解决，再把「症状 → 原因 → 处置」补进技能，使下次不再重踩。
- **自动清理克隆目录**：推送验证成功后自动删除本次克隆的工作目录以节约磁盘——只删该临时 `<workdir>`、不触碰原始 skill 目录；推送失败则保留以便重试。
- **支持非技能项目目录**：不限于 skill 文件夹。对非技能项目会按内容判断 README 是否需更新；若目标为**公开仓库**且项目衍生自**无许可证**的上游代码，会先提示版权 / 再分发风险，你可选择用 `.gitignore` 排除上游衍生文件来降低风险（该 `.gitignore` 写在本地源目录，随同步一并入库）。

## 工作流概览

| 阶段 | 步骤 | 说明 |
|---|---|---|
| 确认目标 | Step 0 | 显式指定本地 skill 路径 + `owner/repo`；核验本地 `SKILL.md` |
| 解析仓库 | Step 1 | `git ls-remote` 探测（按**退出码**区分「不存在」与「空仓库」，不依赖管道退出码）；不存在则引导网页创建；存在则克隆 |
| 检查 README | Step 2 | 缺失则问是否生成；远程 README 与技能内容不一致则问是否按变化更新（按内容判断，不依赖版本号） |
| 泄密 / 隐私检查 | Step 3 | 文件清单、密钥模式、绝对路径、嵌套 `.git`、**本地特定标识（脱敏）**；有疑即停并汇报 |
| 覆盖内容 | Step 4 | `cp -r "<skill-dir>/." "<workdir>/"`（保留仓库独有文件）；源目录若自带 `.git`，改为显式复制并排除 `.git` |
| git 内置验证 | Step 5 | `git status` / `git diff` / `git fsck --full` |
| 提交推送 | Step 6 | `git add -A` → `commit` → `push`；以推送结果确认；若无差异则报告「已同步」、不制造空提交 |
| 自动清理克隆目录 | Step 7 | 推送验证成功后自动 `rm -rf <workdir>`，仅删克隆工作目录、不碰原始 skill；失败则保留 |
| 自我更新 | Step 8 | 记录本次新遇到问题的解决办法 |

## 前置条件（一次性环境）

需要一台已安装 Git for Windows、且能通过 SSH 推送到 GitHub 的机器，验证：

```
ssh -T git@github.com
```

首次配置（用户级免管理员安装、PATH、git 全局、SSH 密钥、GitHub 绑定公钥、提交身份）见仓库内 [`references/setup.md`](./references/setup.md)。

## 安全说明

- 优先使用 SSH，无需在命令或文件中存放任何 token；私钥只保留在本机。
- 不把 `.ssh`、任何凭证文件或技能的本地运行产物纳入版本控制。
- 每次上传 / 更新前执行泄密与隐私检查，任何可疑项都会先汇报给你，由你决定后再继续，避免泄露。
- 远程的创建、目标的选择、README 的生成与更新均由用户显式确认，避免误覆盖。
